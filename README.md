# Генератор карточек товаров для «Союз-Прибора»

Программа готовит черновик карточки для интернет-магазина. Вы передаёте данные одного товара и получаете заголовок, описание, характеристики, поисковые запросы и краткую заметку для менеджера.

## Готовые карточки

Нажмите на название товара, чтобы раскрыть карточку.

**Описание**

МК110-224.8Д.4Р [М01] — изделие производителя ОВЕН. Тип товара — комбинированный модуль ввода/вывода дискретных сигналов. Модуль собирает сигналы со встроенных дискретных входов, передаёт данные в сеть RS-485 и управляет подключёнными исполнительными устройствами на объектах автоматизации.

К входам можно подключать контактные устройства, например кнопки, выключатели, герконы и контакты реле. Поддерживаются также датчики с транзисторным выходом n-p-n с открытым коллектором. Выходы выполнены на электромагнитных реле.

При подборе следует сверить напряжение источника питания, параметры входных сигналов и требования нагрузки. Для выбора программы настройки и проверки дополнительных протоколов нужно уточнить аппаратную версию по маркировке на корпусе.

Дискретные входы — 8. Дискретные релейные выходы — 4. Интерфейс — RS-485. Максимальная скорость обмена по RS-485 — 115200 бит/с. Потребляемая мощность, не более — 6 ВА. Общие для обеих аппаратных версий протоколы — Modbus RTU, Modbus ASCII, ОВЕН. Максимальная частота сигнала на дискретном входе — 1 кГц. Максимальный входной ток — 7 мА.

## Настроить один раз

1. Установите Git, Python 3.9 или новее и Ollama. Ollama запускает модель на вашем компьютере. Для этой модели ключ API не нужен. [Git](https://git-scm.com/install/) · [Python](https://www.python.org/downloads/) · [Ollama](https://docs.ollama.com/quickstart)
2. Откройте терминал. Вводите команды по одной и нажимайте Enter после каждой. Первая команда скачает проект, вторая переведёт терминал в его папку. Если проект уже скачан, откройте терминал в папке, где лежит `cli.py`.

   ```bash
   git clone https://github.com/abdurRahman-sa/souz-pribor-ai-product-card.git
   cd souz-pribor-ai-product-card
   ```

3. Запустите Ollama. Если у вас установлено приложение, откройте его. Для ручного запуска выполните команду в **отдельном окне терминала** и оставьте это окно открытым. [Команды Ollama](https://docs.ollama.com/cli)

   ```bash
   ollama serve
   ```

4. Вернитесь в терминал с папкой проекта и загрузите модель. Дождитесь завершения загрузки. [Модель Qwen3 4B](https://ollama.com/library/qwen3:4b)

   ```bash
   ollama pull qwen3:4b
   ```

## Сделать карточку своего товара

1. В текстовом редакторе создайте файл `my-product.json` в той же папке, где лежит `cli.py`.
2. Скопируйте шаблон и замените текст в кавычках на название и производителя своего товара. Сохраните файл в UTF-8.

   ```json
   {
     "name": "Название товара",
     "manufacturer": "Производитель",
     "specs": {},
     "description": null
   }
   ```

3. Если есть подтверждённые данные, добавьте их перед запуском. Вместо `null` вставьте описание в двойных кавычках. Внутри `specs` укажите названия и значения характеристик в двойных кавычках. Единицы измерения оставьте рядом с числами. Несколько характеристик разделите запятыми. [Образец заполнения](examples/dm02.json)
4. Запустите генератор в терминале с папкой проекта.

   ```bash
   python3 cli.py my-product.json
   ```

С одним названием и производителем программа выдаст короткий черновик и перечислит пропуски. Если вы добавили сведения, но из них всё ещё не получается полное описание на 800–1200 символов, программа может вернуть ошибку. В этом случае дополните данные по паспорту или каталогу производителя и повторите запуск.

## Как читать результат

| Поле в результате | Что с ним делать |
| --- | --- |
| `seo_title` и `seo_description` | Возьмите заголовок и описание как черновик текста для каталога. |
| `specs` | Сверьте характеристики и единицы измерения с документами на товар. |
| `search_queries` | Посмотрите, по каким запросам покупатель может искать товар. |
| `manager_summary` | Прочитайте краткую заметку о назначении товара или о том, каких сведений о нём не хватает. |
| `fieldsToClarify` | Уточните перечисленные сведения. `specs` — характеристики, `description` — описание, `productType` — тип товара, `article` — артикул, `productCode` — код товара. Пустой список `[]` означает, что программа не отметила пропусков во входных полях. |

`isIncomplete: true` означает, что получился короткий черновик. Перед публикацией проверьте технические сведения по источнику и уточните данные, которых не хватает для карточки.

## Технические детали

### Формат входа и выхода

Вход — один объект JSON в UTF-8. `name` и `manufacturer` обязательны и должны быть непустыми строками. `productType` (тип товара), `article` и `productCode` (код товара) — необязательные строки. `description` допускает строку или `null`. `specs` — объект со строковыми названиями и значениями характеристик.

При успехе CLI записывает один JSON-объект в `stdout` и возвращает код `0`. Ошибки чтения, входных данных, Ollama и проверки ответа модели выводятся как JSON в `stderr` с кодом `1`. Проект использует стандартную библиотеку Python.

### Генерация и проверка

1. CLI проверяет вход и собирает список пропусков, затем вызывает локальный API Ollama на `127.0.0.1:11434` с таймаутом 120 секунд. [Документация API Ollama](https://docs.ollama.com/api/chat)
2. Промпт просит модель выбрать заголовок, 3–5 разных поисковых запросов и, для полной карточки, вариант описания. Программа готовит варианты из входных данных. Описание и резюме собираются кодом, характеристики копируются из входа. [Промпт и схема](llm.py) · [Сборка карточки](card.py)
3. CLI проверяет структуру ответа, выбор заголовка и запросов и длину полного описания. При ошибке проверки он один раз передаёт модели список ошибок и проверяет новый ответ. Если название длиннее 70 символов, оно целиком остаётся в описании и запросах, а для заголовка выбирается более короткий вариант.
4. Если описания нет и заполнено не больше одной характеристики, CLI составляет короткий черновик из названия, производителя, типа товара при наличии и списка пропусков.

### Ограничения и развитие

Длина полного описания зависит от входных данных и доступных вариантов сборки. Если после повторной попытки описание не укладывается в 800–1200 символов, CLI сообщает измеренную длину. Можно расширить набор вариантов сборки для других типов приборов, используя их подтверждённые характеристики.
