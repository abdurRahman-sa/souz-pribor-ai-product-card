# Генератор карточек товаров для «Союз-Прибора»

Python CLI принимает JSON с данными одного товара и возвращает черновик карточки для B2B-каталога. В карточку входят SEO-заголовок и описание, характеристики, поисковые запросы, резюме для менеджера и список сведений, которые нужно уточнить.

## Запуск

Понадобятся Git, Python 3.9 или новее и установленная Ollama. Проект использует стандартную библиотеку Python. Модель `qwen3:4b` запускается локально, ключ API для неё не нужен. [Установка Ollama](https://docs.ollama.com/quickstart) · [Модель Qwen3 4B](https://ollama.com/library/qwen3:4b)

1. Склонируйте репозиторий и перейдите в его каталог.

   ```bash
   git clone https://github.com/abdurRahman-sa/souz-pribor-ai-product-card.git
   cd souz-pribor-ai-product-card
   ```

2. Запустите Ollama. Если приложение или служба ещё не запущены, выполните `ollama serve` в отдельном терминале и оставьте его открытым. Загрузите модель.

   ```bash
   ollama pull qwen3:4b
   ```

3. Из корня репозитория запустите CLI для одного или обоих примеров.

   ```bash
   python3 cli.py examples/mk110.json
   python3 cli.py examples/pm01.json
   ```

При успехе CLI записывает один JSON-объект в `stdout` и возвращает код `0`. Ошибки чтения, входных данных, Ollama или проверки ответа модели выводятся как JSON в `stderr` с кодом `1`.

## Примеры

| Товар | Вход | Результат живого запуска |
| --- | --- | --- |
| ОВЕН МК110-224.8Д.4Р [М01] | [Входной JSON](examples/mk110.json) | [Карточка](examples/output/mk110.json) |
| ОВЕН ПМ01-24.АВ | [Входной JSON](examples/pm01.json) | [Карточка](examples/output/pm01.json) |

Во входных данных этих товаров отсутствуют технические характеристики и описание. Поэтому обе карточки содержат короткое фактическое описание, `specs: {}`, `isIncomplete: true` и `fieldsToClarify: ["specs", "description"]`.

## Входной формат

Один JSON-объект в UTF-8. `name` и `manufacturer` — обязательные непустые строки. `productType`, `article` и `productCode` можно передать как строки. `description` допускает строку или `null`. `specs` — объект со строковыми названиями и значениями характеристик. Единицы измерения остаются в значении, например `"0–1,6 МПа"`. Необязательные поля можно опустить.

## Генерация и проверка

1. CLI проверяет вход и определяет, какие сведения нужно уточнить. Затем отправляет данные в локальный `POST /api/chat` на `127.0.0.1:11434` с таймаутом 120 секунд. [Документация API Ollama](https://docs.ollama.com/api/chat)
2. Системный промпт просит писать по-русски и использовать только входные факты. Строки из входного JSON передаются модели как данные. Промпт запрещает выводить характеристики из маркировки и добавлять неподтверждённую совместимость или назначение. [Промпт и JSON-схема](llm.py)
3. CLI проверяет структуру и типы полей, длину заголовка до 70 символов, описание от 800 до 1200 символов при достаточных данных и 3–5 непустых уникальных запросов. При некорректном ответе он один раз передаёт модели список ошибок и проверяет новый ответ. Характеристики копируются из входа.
4. Если описание отсутствует или пустое и заполнено максимум одно значение характеристики, CLI помечает карточку как неполную. Он составляет короткое описание из точного названия, производителя, типа товара при наличии и списка пропусков. Модель выбирает поисковые запросы из вариантов, собранных CLI из входных полей.

## Ограничения и развитие

Проверка формата и длины сама по себе не подтверждает фактическую точность текста модели. Сохранённые карточки вручную сверены с исходными данными. Для новых товаров перед публикацией стоит сверять заголовки и тексты с источником.

Следующее улучшение — добавить автоматическую сверку обозначений и числовых характеристик в сгенерированном тексте с входным JSON и расширить набор примеров товарами с заполненными характеристиками.
